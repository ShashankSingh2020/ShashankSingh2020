## 👋 About Me

Hi, I'm **Shashank Pratap Singh** 👋

I'm a **B.Tech Electronics & Communication Engineering** student at **Bangalore Institute of Technology** (CGPA **8.78**). My degree is in electronics, but my real passion is **software**, specifically the part that happens *behind the screen*: APIs, databases, background jobs, authentication, and the logic that keeps real systems correct.

I enjoy building applications that go **beyond basic CRUD**. That means systems with:

- 🔐 Authentication and role-based access control
- 🏢 Strict separation of data between organizations and workspaces
- ⚙️ Asynchronous processing with background workers
- 📜 Audit trails and event histories for important actions
- 🗄️ Careful database design with constraints and transactions
- 🧪 Automated tests that cover business rules and edge cases

I also like **applied AI**. I don't add an LLM just to say a project has AI. I use it where it solves a real problem: answering questions from private documents (RAG), triaging support tickets, and summarising code-quality reports. Where possible, I pair the AI features with deterministic logic and offline fallbacks so the system still works without them.

On the frontend, I have **basic working knowledge** of React, HTML, CSS, Tailwind, HTMX and Streamlit. I use them to build dashboards and interfaces that make my backends usable.

> 💬 *My goal isn't just to make an application run. It's to make it secure, maintainable, and reliable.*

### ⚡ 1. VoltFleet: EV Fleet Intelligence & Smart Charging

[**View Repository →**](https://github.com/ShashankSingh2020/VoltFleet)

**The problem:** An electric-vehicle fleet produces a constant stream of telemetry (battery level, temperature, charging state). Operators need to know which vehicles need attention, and when and where to charge them cheaply without missing departure deadlines.

**What I built:** A fleet-management platform that ingests vehicle telemetry, schedules charging, detects anomalies, and pushes live updates to a dashboard.

**Key features**

- 📡 **Telemetry ingestion:** validated incoming readings with duplicate handling, so repeated or malformed data doesn't corrupt the records
- 🏢 **Organization boundaries:** each organization sees only its own fleet, with role-based access control
- 🔋 **Smart charging:** charging schedules built from each vehicle's deadline and electricity tariffs
- 🚨 **Anomaly detection:** flags abnormal battery temperature, sudden charge drops, and stale telemetry from vehicles that stopped reporting
- 🔴 **Real-time updates:** live communication using Django Channels and Redis
- 📊 **Dashboard:** a React frontend connected to the backend API

**What it demonstrates:** data validation, scheduling logic, background processing, real-time communication, and clean separation between organizations.

```mermaid
flowchart LR
    A[Vehicle Telemetry] --> B[Validation & Dedup]
    B --> C[(PostgreSQL)]
    C --> D[Celery Workers]
    D --> E[Smart Charging Scheduler]
    D --> F[Anomaly Detection]
    F --> G[Django Channels + Redis]
    E --> G
    G --> H[React Dashboard]
```

**Tech:** `Python` `Django` `DRF` `PostgreSQL` `Redis` `Celery` `Django Channels` `React` `Docker`

### 🧠 2. Enterprise AI Knowledge Engine (RAG Platform)

[**Repository →**](https://github.com/ShashankSingh2020/multi-tenant-rag-engine) · [**Live Application**](https://multi-tenant-rag-engine.streamlit.app) · [**API Documentation**](https://multi-tenant-rag-engine.onrender.com/api/docs/)

**The problem:** Teams have private documents and want accurate answers from them, without sending data to the wrong people and without an LLM making things up.

**What I built:** A document knowledge platform. Users upload documents to their workspace, the system indexes them, and questions are answered by an LLM using only the retrieved, relevant passages, with sources.

**Key features**

- 🏢 **Isolation:** documents are separated at the organization and project level
- 📥 **Async ingestion:** document processing and embedding generation run in background workers, so uploads don't block the API
- 🔎 **Semantic retrieval:** vector similarity search using PostgreSQL with pgvector
- 💬 **Grounded answers:** Google Gemini generates answers from retrieved context, with sources
- 📏 **Quota tracking:** usage limits per organization
- 📜 **Audit logging:** a record of important operations
- 🖥️ **Live demo:** a Streamlit interface plus Swagger/OpenAPI documentation

**What it demonstrates:** an end-to-end RAG pipeline, async workers, vector search in a relational database, and access control around sensitive documents.

```mermaid
flowchart LR
    A[Upload Document] --> B[Celery Worker]
    B --> C[Chunk & Embed]
    C --> D[(PostgreSQL + pgvector)]
    E[User Question] --> F[Embed Query]
    F --> G[Similarity Search]
    D --> G
    G --> H[Gemini LLM]
    H --> I[Grounded Answer + Sources]
```

**Tech:** `Python` `Django` `DRF` `PostgreSQL` `pgvector` `Celery` `Redis` `LangChain / RAG` `Gemini` `Streamlit`

### 🎫 3. Intelligent Support Ticket System

[**View Repository →**](https://github.com/ShashankSingh2020/support-ticket-system)

**The problem:** Support teams need clear ownership, predictable workflows, and a way to notice tickets that are about to breach their service targets.

**What I built:** A backend-focused support platform with role-based workflows, controlled status changes, SLA monitoring, and AI-assisted classification.

**Key features**

- 👥 **Four roles:** customer, agent, manager and admin, each with its own permissions
- 🔄 **Controlled state transitions:** tickets can only move through allowed states, and every change is logged as an event
- ⏱️ **SLA monitoring:** configurable service-level rules checked by background tasks
- ⚙️ **Background processing:** Celery and Redis handle scheduled and long-running work
- 🤖 **AI classification:** Gemini helps categorise tickets, with a **local mock mode** so the system works without an API key
- 📘 **API docs and tests:** documented endpoints and automated tests

**What it demonstrates:** workflow design, permission modelling, event logging, scheduled jobs, and designing AI features that degrade gracefully.

**Tech:** `Python` `Django` `DRF` `PostgreSQL` `Celery` `Redis` `Gemini` `Docker`
